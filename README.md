# TTZip App Core

TTZip Universal Cross-Platform Headless Application Core.

This repository is the standalone, publicly licensed projection of the TTZip
application core. It is self-contained: the Rust crate, the vendored
`ttzip-types` crate, the Swift package, and the artifact generation scripts all
live here, and no monorepo checkout is required.

## Layout

- `src/` — `ttzip-app-core` Rust crate (MTP, ADB, transfer, workspace, UniFFI surface)
- `crates/ttzip-types/` — vendored shared data-type crate
- `Sources/TTZipAppCore/` — Swift target, including generated UniFFI bindings
- `Sources/CTTZipAppCoreBridge/` — C bridge target and public headers
- `Tests/TTZipAppCoreTests/` — Swift package tests
- `scripts/` — artifact generation scripts

## Build

Build the Rust static library and package the XCFramework:

```sh
./scripts/build_rust.sh --debug
```

The script writes `Frameworks/TTZipAppCoreVendor.xcframework` and
`Frameworks/libttzip_desktop.a`. The outbound projection includes the framework.

For a release framework, set `TTZIP_SYS_LIB_DIR` to the staged static
`libdeflate.a`, `liblz4.a`, and `libzstd.a` archives built for macOS 14.0 or
earlier. Include gzip in libdeflate and base, HC, and frame support in LZ4.
For `--universal`, place each architecture's thin archives under `arm64/` and
`x86_64/` in that directory. Release builds compile the pinned libusb source.

## Test

```sh
cargo test --workspace
swift test
```

`swift test` uses the XCFrameworks produced by `scripts/build_rust.sh`.

## UniFFI bindings

`Sources/TTZipAppCore/Generated/ttzip_app_core.swift` and
`Sources/CTTZipAppCoreBridge/include/ttzip_app_coreFFI.h` are generated by `uniffi-bindgen`
and checked in so the package builds without the generator. Regenerate them with:

```sh
cargo install uniffi-bindgen --version 0.28.3
./scripts/generate_uniffi.sh --debug
```

## Reader product

A client can depend on the `TTZipReader` product for Reader persistence.
Clients that import both Swift modules can qualify their Reader types with
`TTZipReader` or `TTZipAppCore`. Both products read the existing on-disk records.
Use one library instance for concurrent writes to a directory.

The Rust bridge is in `crates/ttzip-reader/`. The native storage is in
`crates/ttzip-reader-storage/`. The Swift bindings and C module are in
`Sources/TTZipReader/` and `Sources/CTTZipReaderBridge/`.

`scripts/build_rust.sh` also writes `Frameworks/TTZipReaderVendor.xcframework`.
Regenerate the Reader bindings with:

```sh
cargo build --package ttzip-reader
./scripts/generate_reader_uniffi.sh "$(command -v uniffi-bindgen)" "$PWD/target/debug/libttzip_reader.dylib"
```
